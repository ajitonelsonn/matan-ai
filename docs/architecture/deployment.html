Deployment & security

How MATAN AI ships to AWS — and what it refuses to do with your data

Region us-east-1
No long-lived AWS keys

📦 GitHub repository

Open source · main is the production branch

  • Push triggers an Amplify build
  • .env is never committed

Amplify build

amplify.yml · pnpm via corepack

  • Console variables are copied into .env.production — the SSR runtime does not inherit them
  • Only an allow-list is copied; nothing starting with AWS_

⚙️ Configuration

  • S3_MEDIA_BUCKET, DYNAMODB_TABLE_NAME
  • SES_FROM_EMAIL, SMTP_*, APP_BASE_URL
  • BEDROCK_MODEL_ID, token budget
  • RING_SESSION_SECRET — seals the Ring cookie
  • NEXT_PUBLIC_COGNITO_* — public by design
Amplify Hosting · SSR compute

Next.js server runtime

Short-lived instances behind the Amplify CDN — any request can land on a cold one

  • Ring session travels in a sealed, HttpOnly cookie, so any instance can continue it
  • Scheduler state lives in DynamoDB, not in process memory
  • No fire-and-forget work: analysis and email finish inside the request

🔑 Request identity

  • Cognito access token verified per request (aws-jwt-verify)
  • Everything keyed by the verified sub

Observability

  • Structured logs: sync, analysis, email, runtime_config
  • Never logs tokens, keys or recipients

Data protection

🔒 Boundaries that are enforced, not promised

  • The browser never receives the Ring token, AWS credentials or S3 keys
  • Media is served only through an authenticated route after an ownership check
  • One user's query can only ever read their own partition
  • Deleting an event deletes its media and analysis with it
Reproducible by anyoneProvisioning scripts create the table, bucket and pool; .env.example lists every variable.
Fails loudly, not silentlyOne runtime_config log line per instance says which integrations are actually configured.
