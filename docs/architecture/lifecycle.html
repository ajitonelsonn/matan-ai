From Ring event to a decision you can act on

Application data flow · one Ring event, seven stages, all inside a single server request

measured in production: 2.7 s end to end
Nova Pro 1.4 s
1

Ring records

Motion, package, vehicle or a doorbell press on the Playground device. Matan polls the history and sees a new entry.

Kept: event id, type, device, timestamp, duration
2

🧮 Should we analyze?

Cost and noise gate: skip Matan's own media requests, respect the auto-analysis setting, the hourly budget and the watermark.

Kept: pending list + watermark (AUTO_STATE)
3

📸 Capture evidence

The server pulls the snapshot for the event window from Ring — the clip only when the snapshot is not enough.

Kept: media in S3 (private) + MEDIA# metadata
4

Nova Pro reads it

Amazon Bedrock returns a structured reading: summary, category, confidence, observations and what it is unsure about.

Kept: ANALYSIS# with model id and token usage
5

⚖️ Decision Engine

Deterministic scoring from the reading plus context: security mode, quiet hours, repeats, device. Produces priority and action.

Kept: priority · action · plain-language reasons
6

📏 Smart Rules

Your rules have the last word, in a fixed precedence. The matched rule ids are stored so the UI can explain the outcome.

Kept: careDecision + matched rule ids
7

Tell the human

Notify or Escalate sends one branded email with the analyzed frame, the decision and the reason. Ignore and Monitor stay silent.

Kept: NOTIFICATION# — status, provider, time

📏 How the final decision is reached — first match wins

1 Low-confidence guard — an unsure reading is monitored, never escalated
2 High risk — escalates even during quiet hours
3 Your rules — event type, risk, time window, confidence, repeats
4 Repeated activity — the same thing again within your window
5 Quiet hours — monitor instead of waking you
6 Sensitivity — per event type: low · medium · high
7 Decision Engine default
IGNORE MONITOR NOTIFY → email ESCALATE → email
